# Инженерные футеры и аудитория канала

`display.suppress_engineering_footers_platforms` — список платформ, на которые
не уходят три инженерных футера конца хода:

1. блок «Где выполнялись проверки» (`hermes_cli/run_evidence.py`) — где
   физически исполнялись команды хода;
2. отчёт о неудавшихся записях файлов (`display.file_mutation_verifier`);
3. объяснялка оборванного хода (`display.turn_completion_explainer`) — на
   перечисленных каналах заменяется одной нейтральной строкой, а не убирается
   совсем: молчание в чате читается как «меня проигнорировали».

По умолчанию список пуст — поведение прежнее на всех каналах.

```yaml
display:
  suppress_engineering_footers_platforms: [whatsapp]
```

Значения сравниваются без учёта регистра и пробелов. Любой мусор в значении
(строка вместо списка, отсутствие ключа, ошибка чтения конфига) означает
«не подавлять»: сломанный конфиг обязан давать лишние подробности оператору,
а не тихо выключать анти-оверклейм.

**Что это НЕ закрывает.** На части сбойных ходов телом ответа становится
англоязычная заглушка более глубокого слоя (`⚠️ Provider authentication
failed.`, `⚠️ Session too large for the model's context window.`). Это не
футер, и данный ключ на неё не влияет.

Операторский алерт (`gateway.error_alerts.channel`) на футеры не завязан:
`gateway/turn_error_alerts.py` классифицирует деградацию по собственным
префиксам и флагам результата. Подавление футеров алерт не глушит.
